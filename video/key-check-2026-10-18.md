## Reproducibility

- Firmware binary SHA-256:
  `a9a8c7cedee5ce4012d5aa766ff8a2629e900f08b4bb3e3c42e3aec89678c8a1`
- Committed seed file SHA-256:
  `518f69751ba7e555be05ab66aa808742dc7ab2bc44ba491abce4de404e0274a1`

The refresh used a full flash backup and a separate filesystem backup taken with
the firmware stopped. The filesystem backup and NVS were checked against device
digests before writing. Only `snapshot.json` was replaced in the filesystem image;
the event log was read back from the prepared image and compared byte for byte.
After upload, device digests matched the firmware, prepared filesystem, and
original NVS image. Firmware startup can change filesystem metadata, so compare
live data through the authenticated protocol after the device boots.

The installed legacy `mklittlefs` could not read this image. The refresh used
`littlefs-python==0.19.0`, with 4096-byte blocks, 3312 blocks, 128-byte read/write
units, 512-byte cache, and disk version 2.1, following its
[image inspection documentation](https://littlefs-python.readthedocs.io/en/stable/examples/index.html#inspecting-a-filesystem-image).
No filesystem format or identity reset was used to perform the refresh.
